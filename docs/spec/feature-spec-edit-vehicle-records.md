# Feature spec: Add vehicles and edit vehicle records

Status: Approved (user requests and decisions 2026-11-05/06, issue #42)
Owner: Service Lane Copilot
Updated: 2026-11-06

## User and problem

- User/role: Service advisor.
- Current task or pain: A car that is not in the records cannot be added, and mistakes in a record (vehicle details, a history entry, a recommendation) cannot be corrected.
- Decisions: edit scope covers vehicle details, service history, recommendations, and mileage; every write is logged. MCP write tools and chat confirm cards are a separate ticket; MCP stays read-only here.

## Scope

### In scope (REST API + web UI)

| Route | Purpose |
|---|---|
| `POST /api/vehicles` | Add a vehicle: `serial` (3–32 chars, letters/digits/hyphen, stored upper-case), `make`, `model` (1–40 chars), `year` (1980 to next year), optional `mileage` (integer ≥ 0) with `mileageDate` (not in the future). Starts with no history, no recommendations, `incomplete: true`, completeness "New record – history needed". Existing serial → 409. |
| `PATCH /api/vehicles/{serial}` | Edit `make`, `model`, `year`, and optionally rename the serial (`newSerial`). Renaming to an existing serial → 409. |
| `PUT /api/vehicles/{serial}/history/{index}` | Replace one history entry (`date`, `name`, `detail`, `mileage` or null). Body includes `expected: {date, name}`; mismatch → 409. |
| ~~`DELETE …/history/{index}`~~ | Removed 2026-11-06 (issue #44): service history can be edited but never deleted. |
| `POST /api/vehicles/{serial}/recommendations` | Add an advisor-entered recommendation: `name`, `status` (Due, Coming up, Advisor verification, Not yet due), `text`, `evidence`, optional `rule`, `safety`. Stored with `source: advisor_entered`. |
| `PUT /api/vehicles/{serial}/recommendations/{index}` | Edit one recommendation (`expectedName` guard). Edited recommendations are marked `source: advisor_entered`. |
| `DELETE /api/vehicles/{serial}/recommendations/{index}?expectedName=` | Remove one recommendation (`expectedName` guard). |

- History entries are kept newest-first after edits. Mileage replacement keeps its existing route and form.
- **Change log:** every REST write (these routes plus the existing mileage and completed-service routes) appends `{at (UTC ISO), action, actor: "advisor (web app)", summary}` to the record's `changeLog`; the latest 100 entries are kept. Shown under Record details.
- **UI:** "+ Add vehicle" in Vehicle records and "Add this vehicle" on the not-found result (serial pre-filled); "Edit details" on the vehicle card; edit/delete on each history row (inline "Delete? Yes/No"); "+ Add recommendation" and Edit/Remove on each stored recommendation; Change log list. No browser dialogs.

### Out of scope

- MCP or chat writes (next ticket), deleting whole vehicles, bulk import, undo, user accounts (actor is a fixed label until login exists).

## Safety and data rules

- Synthetic demo data only; the UI states this.
- Advisor-entered recommendations are an approved exception to "recommendations come only from record data and demo rules" (AGENTS.md). They are labelled "Advisor-entered" with their own evidence text and never generated by a model.
- Every failed validation or conflict leaves the record unchanged. Writes use the backend secret key only.
- Index-based edits require the expected entry, so a stale page cannot change the wrong entry.

## Acceptance criteria

1. Add, edit, history edit/delete, and recommendation add/edit/remove succeed for valid input and persist to the database.
2. Unknown serial → 404; invalid input → 422; duplicate serial or stale expected entry → 409; no write in any failure case.
3. Every successful write adds one change-log entry; the log keeps at most 100 entries.
4. A new vehicle opens in the Service lane with recommendations paused and a "history needed" status.
5. MCP tools remained read-only in this ticket; issue #44 adds validated MCP write tools.

## Verification plan

- Live: headless browser flow on a new synthetic test vehicle (add → edit details → add/edit/delete history → add/remove recommendation → change log), then rename it back.
