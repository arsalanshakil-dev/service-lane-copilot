# Feature spec: Manual mileage update

Status: Approved  
Owner: Service Lane Copilot  
Updated: 2026-11-05

## User and problem

- User/role: Service advisor.
- Current task or pain: Obtain a usable odometer reading when OBD-II/CAN does not provide one.
- Evidence or assumptions: The demo uses synthetic records. Several records lack current mileage and service-event mileage. A manual current reading alone does not prove miles since a prior service.

## Outcome and success measure

- Expected outcome: An advisor can replace a missing current mileage in a known synthetic record and record when and how the reading was obtained.
- Measure and baseline: The record returns the updated value and provenance on the next lookup. No numeric performance target is set.

## Scope

### In scope

- Show a manual mileage form for a known record when its current mileage is unavailable.
- Require a non-negative integer mileage, reading date, and source: advisor-observed or customer-reported.
- Save to the local synthetic JSON record, replacing its current mileage and updating its source/date fields.
- Keep recommendations paused when service-history evidence remains incomplete, stale, contradictory, or lacks a mileage reading needed to support the demo recommendation. Never synthesize a service interval or recommendation from mileage alone.
- Expose the update through a local REST endpoint only.

### Out of scope

- Real dealership/customer data, live dealer records, database service, authentication, external lookups, physical OBD-II/CAN access, and updates to service-history events.
- Retaining a previous current mileage after replacement.
- Any write-capable MCP tool or resource.
- Creating or changing maintenance rules.

## User workflow

1. Advisor opens a known synthetic vehicle whose current mileage is unavailable.
2. Advisor enters mileage, date, and whether it was advisor-observed or customer-reported.
3. The app validates the values and saves them to the local synthetic record.
4. The app refreshes the record. It shows the updated mileage and provenance.
5. If service-history evidence is still insufficient or conflicts with the entered reading, recommendations remain paused with the reason displayed.

## Data and source of truth

- Inputs: mileage integer >= 0, date not in the future, source enum `advisor_observed` or `customer_reported`.
- Authoritative source: advisor-entered synthetic demo update for the record's current mileage. The source and date are stored with it.
- Missing/stale/conflicting-data behavior: Unknown serial is 404; invalid payload is 422. A reading below a recorded service mileage is retained as a conflict signal; recommendations remain paused. Missing mileage in service events remains missing.
- Data retained or emitted: Replace `mileage`, set `mileageDate` (ISO date) and `mileageSource`; return the refreshed record. No prior current mileage history is retained.

## Safety, privacy, and approval

- Potential harm if wrong: An incorrect reading can make mileage-based service timing misleading.
- Required human review: Advisor confirms mileage, date, and source before saving; recommendations remain evidence-gated.
- External actions and access: Local synthetic JSON only. REST update route is available to the local demo API. MCP remains read-only and no external system is contacted.

## Failure cases

- Unknown serial number.
- Missing, negative, fractional, malformed, or future-dated values.
- Readings lower than recorded service mileage.
- File write failure.
- Successful mileage write when service history still lacks necessary mileage evidence.

## Acceptance criteria

1. A known record with no current mileage accepts valid mileage, date, and source, persists them to the synthetic data file, and returns the updated record.
2. A later lookup returns the replacement value and provenance.
3. Unknown serials return 404; invalid values return 422 without modifying data.
4. A reading below any recorded service mileage is marked conflicting and recommendations stay paused.
5. Missing service-event mileage or incomplete service history remains missing/incomplete after update; the UI explains that mileage alone is insufficient.
6. The UI provides the update form only when current mileage is unavailable and refreshes the record after save.
7. No recommendation or maintenance interval is generated by the update route. MCP remains read-only.
